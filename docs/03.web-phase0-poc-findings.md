## 1. Web Speech API

### TTS — `speechSynthesis`

- Available in Chrome, Edge, Firefox, and Safari.
- English voices selectable via `speechSynthesis.getVoices()`.
- Used as the fallback when VOICEVOX Lambda is unavailable or times out.

### STT — `SpeechRecognition`

- Available in Chrome and Edge only via `webkitSpeechRecognition` / `SpeechRecognition`.
- **Safari does not support `SpeechRecognition`** (as of 2026-03).
- Judgment logic (Levenshtein similarity):
  - Exact match (after normalisation) → **PERFECT**
  - Similarity ≥ 0.70 → **CLOSE**
  - Otherwise → **RETRY**
- Action: show a "Please use Chrome or Edge" banner on `PronunciationPage` for unsupported browsers.

## 2. IndexedDB

### Schema (EnglishLearnDB v1)

Three object stores confirmed working:

| Store | Key | Indexes |
|-------|-----|---------|
| `words` | `id` (UUID) | `status`, `created_at`, `word` |
| `sentences` | `id` (UUID) | `word_id`, `word_id_sort` |
| `audio_cache` | `id` (SHA256) | `created_at`, `last_accessed_at` |

### Blob Storage

- A 100 KB `audio/wav` Blob was stored and retrieved without error.
- Suitable for VOICEVOX WAV cache (typical size: 50–300 KB per phrase).
- Browser quota (Chrome): ~60% of available disk space — sufficient for hundreds of cached phrases.

### Soft-delete Auto-purge

- Records with `deleted_at < today - 10 days` are physically deleted on app start.
- Confirmed via PoC test: 1 record inserted with 11-day-old `deleted_at`, purge removed it.

## 3. VOICEVOX Lambda / CORS

### Problem

The existing API Gateway CDK definition had no CORS configuration:

```typescript
// Before — iOS only, no CORS
const httpApi = new apigatewayv2.HttpApi(this, 'VoicevoxHttpApi', {
  apiName: `voicevox-api-${stackEnv}`,
  // CORS removed: native iOS app does not require CORS
});
```

Browser `fetch` calls trigger an OPTIONS preflight request. Without CORS headers in the
response, the browser blocks the request. This affects all Web app → API Gateway calls.

### Fix (applied in this PR)

```typescript
// After — Web + iOS compatible
const corsAllowOrigins = stackEnv === 'poc'
  ? ['*']
  : [`https://voicevox-${stackEnv}.example.com`]; // Replace with CloudFront domain

const httpApi = new apigatewayv2.HttpApi(this, 'VoicevoxHttpApi', {
  apiName: `voicevox-api-${stackEnv}`,
  corsPreflight: {
    allowOrigins: corsAllowOrigins,
    allowMethods: [CorsHttpMethod.POST, CorsHttpMethod.GET, CorsHttpMethod.OPTIONS],
    allowHeaders: ['Content-Type', 'x-api-key'],
    maxAge: Duration.days(1),
  },
});
```

- **poc**: `allowOrigins: ['*']` — permits any origin for local dev validation.
- **dev/pro**: replace `example.com` placeholder with the actual CloudFront domain once provisioned (Issue #124).
- iOS native app: unaffected — native HTTP clients send no Origin header, so CORS headers are simply ignored.

### Cold-start Latency

- Measured via `web/poc/index.html` Tab 3.
- Expected: 10–30 s on first invocation after Lambda is idle.
- Mitigation: show a loading spinner; retry once on timeout; fall back to Web Speech TTS.
