# ローカルの Docker で VOICEVOX を使う

Web 版のずんだもん音声を、手元の Docker で動かす VOICEVOX Engine で再生する手順です。AWS のスタックも API キーも要りません。

2026-11-10 に、Apple Silicon の Mac(Rancher Desktop、Docker 29.5.2)と VOICEVOX Engine 0.25.1(`cpu-0.25.1`、`linux/arm64`)で、この手順どおりに動くことを確かめました。

## 1. エンジンを起動する

VOICEVOX Engine の公式 README にあるコマンドを、バージョンを固定して使います。`127.0.0.1` にだけ公開するので、同じ LAN の他の端末からは使えません。

```bash
docker run --rm -p '127.0.0.1:50021:50021' voicevox/voicevox_engine:cpu-0.25.1
```

バージョンは AWS 側のスタック(`voicevox_engine` 0.25.1)と揃えています。アプリは話者 ID(ずんだもんのスタイル)を決め打ちしているので、別のバージョンにするときは、設定画面のスタイルがすべて鳴るか確かめてください。

初回はイメージの取得に時間がかかります。起動したかは次のコマンドで確かめられます。バージョン番号が返れば準備完了です。

```bash
curl http://127.0.0.1:50021/version
```

止めるときは、起動したターミナルで `Ctrl+C` を押します。`--rm` を付けているので、止めるとコンテナも消えます。

## 2. アプリの接続先を変える

アプリを起動し、設定画面の「VOICEVOX設定」にある接続先の欄に、次の URL を入力します。入力した値はすぐに保存され、次の再生から使われます。`.env` の書き換えや、開発サーバーの再起動は要りません。

```text
http://127.0.0.1:50021
```

入力したら「接続テスト」を押します。「接続できました（VOICEVOX 0.25.1）」と出れば準備完了です。接続テストは `/speakers` を呼ぶので、AWS では API キーが正しいかどうかも確かめられます(`/version` はキーなしで通るため、キーの確認には使えません)。

アプリは http://localhost:5173/ で開いてください。単語データ、キャッシュ、設定は開いた URL(ポート番号を含む)ごとに保存されるので、別のポートで開くと、登録した単語も入力した接続先も見えません。

キーの扱いは次のとおりです。

- ローカルのエンジンにはキーが要りません。キーなしで送るのは、接続先が `localhost`、`127.0.0.1`、`[::1]` のときだけです。
- `web/.env` に入っている AWS のキー(`VITE_VOICEVOX_API_KEY_POC`)は、接続先が `.env` の接続先と同じときだけ送ります。設定画面で別の接続先を入れても、そこへは送りません。
- 設定画面の「VOICEVOX設定」に入力した API キーは、入力したときの接続先(のスキーム、ホスト、ポート)にだけ送ります。AWS のキーを入れたままローカルに切り替えても、ローカルには送らず、AWS に戻すとまた使います。
- ローカル以外の接続先にキーがないときは、通信せずにブラウザの声で読みます。AWS の接続先にキーなしで送ると 401 になり、API の 4xx アラームに数えられるためです。

## 3. 再生する

1. 設定画面で、日本語の音声を「ずんだもん」にします(初期値)。英語もずんだもんで聞くときは、「英語の音声設定」で選びます。
2. 例文一覧の「日本語を聞く」などで再生します。「全て再生」で連続再生もできます。

1回目はエンジンで音声を合成するので、少し時間がかかります。同じ文の2回目からは、ブラウザの音声キャッシュから再生されます。キャッシュは接続先ごとに分かれるので、AWS とローカルを切り替えても、別のエンジンの音声が混ざることはありません。

## 4. 動作を確かめる(任意)

- **通信:** DevTools の Network タブで、`127.0.0.1:50021` への `/audio_query` と `/synthesis` が 200 で返り、リクエストヘッダーに `x-api-key` がないことを確かめます。Console に CORS エラーが出ていないことも見ます。
- **スタイルの切り替え:** 設定画面の「VOICEVOX設定」でスタイルを変えて再生すると、声が変わります。新しいスタイルの1回目は合成し直します。
- **エンジン停止時の切り替え:** エンジンを止めてから、まだ聞いていない文を再生すると、ブラウザの声で読みます。エラーで止まることはありません。一度聞いた文はキャッシュから再生されるので、エンジンを止めても、ずんだもんの声のままです。

## 5. 元に戻す

設定画面の接続先の欄で「既定に戻す」を押します。欄が空になり、`web/.env` の接続先(AWS)に戻ります。

エンジンは、起動したターミナルで `Ctrl+C` を押して止めます。

## うまくいかないとき

| 症状 | 確かめること |
| --- | --- |
| ずんだもんではなく、ブラウザの声で読まれる | エンジンが起動しているか(`curl http://127.0.0.1:50021/version`)。設定画面の接続先が `http://127.0.0.1:50021` になっていて、「接続テスト」が通るか |
| コンソールに CORS エラーが出る | アプリを `localhost` か `127.0.0.1` で開いているか。エンジンの既定の CORS 設定(`localapps`)は、この2つからのアクセスだけを許可する。手元では `http://localhost:5174` から `/audio_query` と `/synthesis` が通ることを確かめた |
| LAN の別の端末から開くと鳴らない | 想定どおりの動作。エンジンを `127.0.0.1` にだけ公開しているうえ、その端末から見た `127.0.0.1` は端末自身になる |

iOS 版は対象外です。iPhone から見た `localhost` は iPhone 自身なので、Mac のエンジンに届けるには LAN のアドレス、ATS の例外設定、`127.0.0.1` 以外への公開が必要になります。
