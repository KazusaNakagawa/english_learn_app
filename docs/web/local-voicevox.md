# ローカルの Docker で VOICEVOX を使う

Web 版のずんだもん音声を、手元の Docker で動かす VOICEVOX Engine で再生する手順です。AWS のスタックも API キーも要りません。

2026-11-10 に、Apple Silicon の Mac(Rancher Desktop、Docker 29.5.2)と VOICEVOX Engine 0.26.1(`cpu-latest`、`linux/arm64`)で、この手順どおりに動くことを確かめました。

## 1. エンジンを起動する

VOICEVOX Engine の公式 README にあるコマンドです。`127.0.0.1` にだけ公開するので、同じ LAN の他の端末からは使えません。

```bash
docker run --rm -p '127.0.0.1:50021:50021' voicevox/voicevox_engine:cpu-latest
```

初回はイメージの取得に時間がかかります。起動したかは次のコマンドで確かめられます。バージョン番号が返れば準備完了です。

```bash
curl http://127.0.0.1:50021/version
```

止めるときは、起動したターミナルで `Ctrl+C` を押します。`--rm` を付けているので、止めるとコンテナも消えます。

## 2. アプリの接続先を変える

`web/.env` の VOICEVOX の設定を、次のように書き換えます。ローカルのエンジンにはキーが要らないので、キーは空にします。

```bash
VITE_VOICEVOX_ENDPOINT_POC=http://127.0.0.1:50021
VITE_VOICEVOX_API_KEY_POC=
```

接続先はビルド時に埋め込まれるので、書き換えたら開発サーバー(`npm run dev`)を起動し直してください。設定画面で接続先を変えられるようにする作業は #204 で扱います。

設定画面の「VOICEVOX設定」に API キーを入れている場合は、空にしてください。キーがあると `x-api-key` ヘッダーを付けて送ります。

## 3. 再生する

1. 設定画面で、日本語の音声を「ずんだもん」にします(初期値)。
2. 例文一覧の「日本語を聞く」などで再生します。

1回目はエンジンで音声を合成するので、少し時間がかかります。同じ文の2回目からは、ブラウザの音声キャッシュから再生されます。

## うまくいかないとき

| 症状 | 確かめること |
| --- | --- |
| ずんだもんではなく、ブラウザの声で読まれる | エンジンが起動しているか(`curl http://127.0.0.1:50021/version`)。`.env` を書き換えた後に開発サーバーを起動し直したか |
| コンソールに CORS エラーが出る | アプリを `localhost` か `127.0.0.1` で開いているか。エンジンの既定の CORS 設定(`localapps`)は、この2つからのアクセスだけを許可する。手元では `http://localhost:5174` から `/audio_query` と `/synthesis` が通ることを確かめた |
| LAN の別の端末から開くと鳴らない | 想定どおりの動作。エンジンを `127.0.0.1` にだけ公開しているうえ、その端末から見た `127.0.0.1` は端末自身になる |

iOS 版は対象外です。iPhone から見た `localhost` は iPhone 自身なので、Mac のエンジンに届けるには LAN のアドレス、ATS の例外設定、`127.0.0.1` 以外への公開が必要になります。
