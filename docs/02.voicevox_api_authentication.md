# VOICEVOX API 認証ガイド

VOICEVOX TTS API のアクセスコントロール設定について説明します。

## アーキテクチャ

```bash
iOS App
  │
  │  x-api-key: <API_KEY>
  ▼
API Gateway (HTTP API)
  │
  ├── Lambda Authorizer (voicevox-authorizer-{env})
  │     └── x-api-key ヘッダーを検証
  │
  └── Lambda (voicevox-engine-{env})
        └── VOICEVOX TTS 処理
```

### 認証フロー

1. iOS アプリがリクエストに `x-api-key` ヘッダーを付与
2. API Gateway が Lambda Authorizer を呼び出し
3. Authorizer が API キーを検証し、`isAuthorized: true/false` を返却
4. 認証成功時のみ VOICEVOX Lambda にリクエストが転送される

### エンドポイント別の認証要否

| エンドポイント | メソッド | 認証 | 用途 |
|---------------|---------|------|------|
| `/audio_query` | POST | 必要 | テキスト → クエリJSON 生成 |
| `/synthesis` | POST | 必要 | クエリJSON → WAV 音声合成 |
| `/speakers` | GET | 必要 | 話者一覧取得 |
| `/version` | GET | 不要 | ヘルスチェック |

## セットアップ手順

### 1. API キーの生成

環境ごとに固有の API キーを生成します（64文字の16進数文字列）。

```bash
# PoC 環境
export VOICEVOX_API_KEY_POC="$(openssl rand -hex 32)"
echo "PoC API Key: $VOICEVOX_API_KEY_POC"

# Dev 環境
export VOICEVOX_API_KEY_DEV="$(openssl rand -hex 32)"

# Pro 環境
export VOICEVOX_API_KEY_PRO="$(openssl rand -hex 32)"
```

**重要:** 生成した API キーは安全な場所に保存してください。スタック削除後は復元できません。

### 2. CDK スタックのデプロイ

```bash
cd aws

# PoC 環境にデプロイ
npm run deploy:poc

# デプロイ完了後、出力を確認
# - VoicevoxApiEndpoint: API のベース URL

# API キーは環境変数 VOICEVOX_API_KEY_POC に設定した値を使用
echo $VOICEVOX_API_KEY_POC
```

### 3. iOS アプリの設定

`EnglishLearnApp/EnglishLearnApp/AppConfig.swift` を更新：

```swift
enum AppConfig {
    static let voicevoxBaseURL = "https://<API_ID>.execute-api.ap-northeast-1.amazonaws.com"
    static let voicevoxApiKey = "<YOUR_API_KEY>"
}
```

## 動作確認

### API キーなし（403 を期待）

```bash
ENDPOINT="https://<API_ID>.execute-api.ap-northeast-1.amazonaws.com"

curl -X POST "$ENDPOINT/audio_query?text=test&speaker=3"
# → {"message":"Forbidden"}
```

### API キーあり（200 を期待）

```bash
curl -X POST "$ENDPOINT/audio_query?text=test&speaker=3" \
  -H "x-api-key: $VOICEVOX_API_KEY_POC"
# → {"accent_phrases":[...], ...}
```

### ヘルスチェック（認証不要）

```bash
curl "$ENDPOINT/version"
# → "0.25.1"
```

### 音声合成の通しテスト

```bash
# Step 1: audio_query
curl -G -X POST "$ENDPOINT/audio_query" \
  --data-urlencode "text=ずんだもんです" \
  -d "speaker=3" \
  -H "x-api-key: $VOICEVOX_API_KEY_POC" \
  -o query.json

# Step 2: synthesis
curl -X POST "$ENDPOINT/synthesis?speaker=3" \
  -H "Content-Type: application/json" \
  -H "x-api-key: $VOICEVOX_API_KEY_POC" \
  -d @query.json \
  -o output.wav

# Step 3: 再生確認 (macOS)
afplay output.wav
```

## トラブルシューティング

### `{"message":"Forbidden"}` が返る

**原因:** API キーが無効または未設定

**確認事項:**
1. `x-api-key` ヘッダーが正しく設定されているか
2. API キーの値がデプロイ時の環境変数と一致しているか
3. iOS アプリの `AppConfig.voicevoxApiKey` が正しいか

```bash
# デプロイ時に使用した API キーを確認（環境変数）
echo $VOICEVOX_API_KEY_POC

# セキュリティ上の理由により、CloudFormation Output からは取得できません
# デプロイ時に設定した環境変数の値を使用してください
```

### `{"message":"Unauthorized"}` が返る

**原因:** Authorizer Lambda の実行エラー

**確認事項:**
- CloudWatch Logs で `voicevox-authorizer-poc` のログを確認

### `{"message":"Not Found"}` が返る

**原因:** 存在しないパスにアクセスしている

**確認事項:**
- URL に `/audio_query`, `/synthesis`, `/speakers`, `/version` のいずれかが含まれているか
- ルートパス (`/`) にはルートが設定されていません

### Lambda コンソールの警告メッセージ

```
The API with ID xxx doesn't include a route with path /* having an integration ...
```

これは CDK が生成するリソースベースポリシーの説明文であり、**実際の動作には影響しません**。無視して問題ありません。

## API キーのローテーション

API キーを変更する場合：

1. 新しい API キーを生成
   ```bash
   export VOICEVOX_API_KEY_POC="$(openssl rand -hex 32)"
   ```

2. スタックを再デプロイ
   ```bash
   npm run deploy:poc
   ```

3. iOS アプリの `AppConfig.swift` を更新

4. アプリを再ビルド・配布

**注意:** キー変更後、古いキーを使用しているアプリは即座に 403 エラーになります。

## セキュリティ考慮事項

### 現在の実装

- API キーは Lambda Authorizer の環境変数に保存
- キャッシュ TTL: 5分（同一キーでの連続リクエストは Authorizer をスキップ）
- レート制限: 環境ごとに設定（poc: 5 RPS, dev: 10 RPS, pro: 50 RPS）

### 将来の改善案

- AWS Secrets Manager での API キー管理（自動ローテーション対応）
- Cognito User Pools によるユーザー認証（マルチユーザー対応時）
- WAF による追加の保護層
