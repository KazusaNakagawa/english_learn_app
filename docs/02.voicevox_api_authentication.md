# VOICEVOX API 認証ガイド

VOICEVOX TTS API のアクセスコントロール設定について説明します。

## アーキテクチャ

```bash
iOS App
  │
  │  x-api-key: <API_KEY>
  ▼
API Gateway (HTTP API)
  │
  ├── Lambda Authorizer (voicevox-authorizer-{env})
  │     └── x-api-key ヘッダーを検証
  │
  └── Lambda (voicevox-engine-{env})
        └── VOICEVOX TTS 処理
```

### 認証フロー

1. iOS アプリがリクエストに `x-api-key` ヘッダーを付与
2. API Gateway が Lambda Authorizer を呼び出し
3. Authorizer が API キーを検証し、`isAuthorized: true/false` を返却
4. 認証成功時のみ VOICEVOX Lambda にリクエストが転送される

### エンドポイント別の認証要否

| エンドポイント | メソッド | 認証 | 用途 |
|---------------|---------|------|------|
| `/audio_query` | POST | 必要 | テキスト → クエリJSON 生成 |
| `/synthesis` | POST | 必要 | クエリJSON → WAV 音声合成 |
| `/speakers` | GET | 必要 | 話者一覧取得 |
| `/version` | GET | 不要 | ヘルスチェック |

## セットアップ手順

### 1. API キーを Secrets Manager に作成する

環境ごとに固有の API キーを生成し、**Secrets Manager に置きます**（64文字の16進数文字列）。
CDK スタックはこのシークレットの**名前だけ**を知っており、値は Lambda が実行時に読みます。
デプロイする人の手元に API キーは必要ありません (#182)。

```bash
# PoC 環境（スタックと同じリージョンに作ること）
aws secretsmanager create-secret \
  --name /englishlearn/poc/voicevox/api-key \
  --description "VOICEVOX API key (poc)" \
  --secret-string "$(openssl rand -hex 32)" \
  --region ap-northeast-1

# dev / pro も同様（poc を dev / pro に読み替える）
```

| シークレット名 | 用途 | 読む関数 |
| --- | --- | --- |
| `/englishlearn/{env}/voicevox/api-key` | API キー | `voicevox-authorizer-{env}` |
| `/englishlearn/{env}/voicevox/slack-webhook-url` | Slack Webhook URL（任意） | `voicevox-slack-alert-{env}` |

作成前にデプロイしても失敗はしませんが、シークレットが無い間は Authorizer が
すべてのリクエストを拒否します（fail closed）。

**重要:** シークレットを削除すると 7〜30 日の復旧待機期間に入り、その間は
**同名で作り直せません**。スタックとは独立に管理される（`cdk destroy` では消えない）のは
そのためです。

### 2. CDK スタックのデプロイ

```bash
cd aws

# PoC 環境にデプロイ（API キーの環境変数は不要）
npm run deploy:poc

# デプロイ完了後、出力を確認
# - VoicevoxApiEndpoint: API のベース URL
```

iOS アプリや curl に設定する値は、シークレットから取り出します。

```bash
export VOICEVOX_API_KEY_POC="$(aws secretsmanager get-secret-value \
  --secret-id /englishlearn/poc/voicevox/api-key \
  --query SecretString --output text)"
```

> この読み出しには `secretsmanager:GetSecretValue` が必要です。`readonly` / `audit`
> グループは `deny-secret-reads` で拒否されます（[05.iam_group_design.md](05.iam_group_design.md)）。

### 3. iOS アプリの設定

`EnglishLearnApp/EnglishLearnApp/AppConfig.swift` を更新：

```swift
enum AppConfig {
    static let voicevoxBaseURL = "https://<API_ID>.execute-api.ap-northeast-1.amazonaws.com"
    static let voicevoxApiKey = "<YOUR_API_KEY>"
}
```

## 動作確認

### API キーなし（403 を期待）

```bash
ENDPOINT="https://<API_ID>.execute-api.ap-northeast-1.amazonaws.com"

curl -X POST "$ENDPOINT/audio_query?text=test&speaker=3"
# → {"message":"Forbidden"}
```

### API キーあり（200 を期待）

```bash
curl -X POST "$ENDPOINT/audio_query?text=test&speaker=3" \
  -H "x-api-key: $VOICEVOX_API_KEY_POC"
# → {"accent_phrases":[...], ...}
```

### ヘルスチェック（認証不要）

```bash
curl "$ENDPOINT/version"
# → "0.25.1"
```

### 音声合成の通しテスト

```bash
# Step 1: audio_query
curl -G -X POST "$ENDPOINT/audio_query" \
  --data-urlencode "text=ずんだもんです" \
  -d "speaker=3" \
  -H "x-api-key: $VOICEVOX_API_KEY_POC" \
  -o query.json

# Step 2: synthesis
curl -X POST "$ENDPOINT/synthesis?speaker=3" \
  -H "Content-Type: application/json" \
  -H "x-api-key: $VOICEVOX_API_KEY_POC" \
  -d @query.json \
  -o output.wav

# Step 3: 再生確認 (macOS)
afplay output.wav
```

## トラブルシューティング

### `{"message":"Forbidden"}` が返る

**原因:** API キーが無効または未設定

**確認事項:**
1. `x-api-key` ヘッダーが正しく設定されているか
2. API キーの値がシークレットの現在値と一致しているか
3. iOS アプリの `AppConfig.voicevoxApiKey` が正しいか
4. シークレットが作成済みか（未作成なら Authorizer は全拒否し、CloudWatch Logs に
   `Failed to read the API key secret` が出る）

```bash
# 現在の API キーを確認
aws secretsmanager get-secret-value \
  --secret-id /englishlearn/poc/voicevox/api-key \
  --query SecretString --output text

# セキュリティ上の理由により、CloudFormation Output からは取得できません
```

### `{"message":"Unauthorized"}` が返る

**原因:** Authorizer Lambda の実行エラー

**確認事項:**
- CloudWatch Logs で `voicevox-authorizer-poc` のログを確認

### `{"message":"Not Found"}` が返る

**原因:** 存在しないパスにアクセスしている

**確認事項:**
- URL に `/audio_query`, `/synthesis`, `/speakers`, `/version` のいずれかが含まれているか
- ルートパス (`/`) にはルートが設定されていません

### Lambda コンソールの警告メッセージ

```
The API with ID xxx doesn't include a route with path /* having an integration ...
```

これは CDK が生成するリソースベースポリシーの説明文であり、**実際の動作には影響しません**。無視して問題ありません。

## API キーのローテーション

**再デプロイは不要です**（#182）。シークレットの値を差し替えるだけです。

1. 新しい値を書き込む
   ```bash
   aws secretsmanager put-secret-value \
     --secret-id /englishlearn/poc/voicevox/api-key \
     --secret-string "$(openssl rand -hex 32)"
   ```

2. 反映を待つ（最大 **約10分**）
   - Authorizer Lambda のシークレットキャッシュ: 最大 5 分（温まったコンテナが
     旧キーを保持しうる時間）
   - API Gateway の Authorizer 結果キャッシュ: 最大 5 分。**拒否もキャッシュされる**ため、
     旧キーを保持したコンテナが新キーを一度拒否すると、さらに 5 分間拒否が続く
   - つまり最悪ケースは 5 分 + 5 分。急ぐなら新旧の切り替え前にこの待ち時間を見込む

3. iOS アプリの `AppConfig.swift` を更新

4. アプリを再ビルド・配布

**注意:** 反映後、古いキーを使用しているアプリは 403 エラーになります。
新旧どちらも通る期間は作れないため、アプリ側の更新を先に配布してから切り替えます。

## セキュリティ考慮事項

### 現在の実装

- API キーは **Secrets Manager** に保存し、Authorizer Lambda が実行時に読む (#182)
  - Lambda 環境変数に入るのはシークレット**名**のみ。`ReadOnlyAccess` に含まれる
    `lambda:GetFunctionConfiguration` は環境変数を平文で返すため、値を置くと
    読み取り専用の権限だけで API キーが読めてしまう（#173 で発見）
  - CloudFormation テンプレート・`cdk.out`・デプロイ端末の shell 履歴にも残らない
  - 各関数に与える `secretsmanager:GetSecretValue` は自分のシークレット 1 本のみ
- シークレットキャッシュ TTL: 5分（ローテーションが効くまでの上限）
- Authorizer 結果キャッシュ TTL: 5分（同一キーでの連続リクエストは Authorizer をスキップ）
- レート制限: 環境ごとに設定（poc: 5 RPS, dev: 10 RPS, pro: 50 RPS）

### 将来の改善案

- Secrets Manager の自動ローテーション（Lambda ローテータの追加）
- Cognito User Pools によるユーザー認証（マルチユーザー対応時）
- WAF による追加の保護層
