# ずんだもん音声サービス クラウド構成要件 (PoC)

## 背景

- 現状: ずんだもん (VOICEVOX) をローカルで起動し、アプリから呼び出している
- 課題: 本番ローンチ時にクラウド上で動かす必要があるが、EC2 を常時起動するとコスパが悪い
- 方針: PoC 段階では「動けばよい」をゴールとし、最小コストで検証する

## 対象サービス比較

### Option A: AWS Lambda (Container Image) ← PoC 推奨

| 項目 | 内容 |
| ------ | ------ |
| 方式 | VOICEVOX Docker イメージを Lambda Container Image としてデプロイ |
| アイドルコスト | $0 (未使用時は課金なし) |
| 課金 | リクエスト数 + GB-秒 (Free Tier: 1M req/月 + 400,000 GB-秒/月) |
| PoC 月額概算 | ほぼ $0〜数十円 |
| コールドスタート | 初回リクエスト時に 10〜30 秒程度の遅延あり |
| メモリ上限 | 10 GB (VOICEVOX の要件を満たす) |
| タイムアウト上限 | 15 分 (TTS 生成には十分) |
| GPU | 非対応 (CPU 推論のみ) |
| セットアップ難易度 | 低い |

#### PoC 構成イメージ

```bash
iOS App
  └── API Gateway (HTTP API)
        └── Lambda (VOICEVOX Container Image)
              └── 音声データを Base64 or S3 presigned URL で返却
```

#### 注意点
- コールドスタートの遅延は PoC では許容する
- 本番移行時は Provisioned Concurrency や ECS Fargate への移行を検討
- Lambda の /tmp ストレージは 10 GB (音声ファイルの一時保存に使用可能)

---

### Option B: ECS Fargate (scale-to-zero)

| 項目 | 内容 |
| ----- | ----- |
| 方式 | ECS Fargate + Application Auto Scaling でタスク数 0 にスケールダウン |
| アイドルコスト | スケールゼロ設定で $0 (ただし設定が複雑) |
| 課金 | vCPU/秒 + GB/秒 (0.5 vCPU + 1 GB = 約 $0.024/時) |
| PoC 月額概算 | 稼働時間次第で $1〜10/月 |
| コールドスタート | スケールゼロからの起動は 1〜2 分 |
| セットアップ難易度 | 高い (ALB + Auto Scaling + タスク定義など) |

---

## PoC の判断

**Lambda (Container Image) を採用する。**

理由:
1. アイドル時コストがゼロで、PoC のトラフィック規模では Free Tier 内に収まる
2. VOICEVOX の Docker イメージをそのまま利用できる
3. セットアップが容易で検証速度が高い
4. コールドスタートの遅延は PoC 段階では許容範囲

---

## 本番移行時の追加検討事項

- コールドスタート対策: Provisioned Concurrency または ECS Fargate への移行
- レスポンス最適化: 音声ファイルを S3 にキャッシュし、同一テキストの再生成を省略
- GPU 推論: より高品質・高速化が必要な場合は ECS on EC2 (GPU インスタンス) を検討
- セキュリティ: API Gateway に認証 (Cognito or API Key) を追加
