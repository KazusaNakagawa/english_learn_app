# VOICEVOX Lambda デプロイ 対応記録

AWS Lambda (Container Image) 上で VOICEVOX engine を動かすまでに発生したエラーと解決策をまとめます。

---

## 最終構成

```
iOS App
  └── API Gateway (HTTP API)
        └── Lambda (Container Image)
              ├── Lambda Web Adapter (Extension)  ← HTTP ⇔ Lambda を橋渡し
              └── VOICEVOX engine (port 50021)
```

### 最終 Dockerfile

最新の内容は [`aws/lambda/voicevox/Dockerfile`](../aws/lambda/voicevox/Dockerfile) を参照してください。

## 対応したエラー一覧

### 1. `{"message":"Bad Request"}`

**症状**
`/audio_query` を叩くと API Gateway から Bad Request が返る。

**原因**
`text` と `speaker` クエリパラメータなしでリクエストしていた。

**解決策**
```bash
curl -G -X POST "${BASE_URL}/audio_query" \
  --data-urlencode "text=ずんだもんです" \
  -d "speaker=3" \
  -o query.json
```

---

### 2. `Runtime.ExitError` (Init Duration: 14ms)

**症状**
Lambda が即クラッシュ。Init Duration が 14ms と極端に短い。

**原因 A: Apple Silicon (ARM) でビルドしたイメージを x86_64 Lambda で実行**
CDK がデフォルトでホスト CPU アーキテクチャ向けにビルドするため、M1/M2/M3 Mac では ARM イメージが生成される。

**解決策**
`voicevox-stack.ts` でプラットフォームを明示指定。

```typescript
import * as ecr_assets from 'aws-cdk-lib/aws-ecr-assets';

code: lambda.DockerImageCode.fromImageAsset(
  path.join(__dirname, '../lambda/voicevox'),
  { platform: ecr_assets.Platform.LINUX_AMD64 }
),
```

**原因 B: Dockerfile の CMD パスが誤っていた**
`CMD ["python", "./run.py", ...]` と記述していたが、イメージに `run.py` は存在しない。

```bash
# Dockerfile で使用しているイメージタグを確認してから実行する
# 例: cpu-ubuntu22.04-0.25.1 の場合
BASE_IMAGE=$(grep '^FROM voicevox' aws/lambda/voicevox/Dockerfile | tail -1 | awk '{print $2}')
docker pull --platform linux/amd64 "${BASE_IMAGE}"
docker inspect "${BASE_IMAGE}" --format '{{json .Config.Cmd}}'
```

---

### 3. `failed switching to "user": no matching entries in passwd file`

**症状**
```
error: failed switching to "user": unable to find user user: no matching entries in passwd file
```

**原因**
ベースイメージのデフォルト CMD が `gosu user python3 ...` で、`user` ユーザーへの切り替えを行う。
Lambda コンテナは root で動作するため `gosu` によるユーザー切り替えが失敗する。

**解決策**
Dockerfile で `gosu user` を除いた CMD に上書き。

```dockerfile
WORKDIR /opt/voicevox_engine
CMD ["/opt/python/bin/python3", "./run.py", \
     "--voicelib_dir", "/opt/voicevox_core/", \
     "--runtime_dir", "/opt/onnxruntime/lib", \
     "--host", "0.0.0.0", \
     "--port", "50021"]
```

### 4. `ModuleNotFoundError: No module named 'uvicorn'`

**症状**
```
File "/opt/voicevox_engine/./run.py", line 13, in <module>
    import uvicorn
ModuleNotFoundError: No module named 'uvicorn'
```

**原因**
`uvicorn` 等のパッケージはベースイメージ内で `user` アカウントのホームディレクトリ
(`/home/user/.local/lib/python3.x/site-packages`) にインストールされている。
root で実行すると Python がこのパスを参照しない。

**解決策**
`HOME=/home/user` を設定し、Python が `/home/user/.local` を参照するようにする。

```dockerfile
ENV HOME=/home/user
```

---

### 5. `OSError: [Errno 30] Read-only file system: '/home/user/.local/share'`

**症状**
```
OSError: [Errno 30] Read-only file system: '/home/user/.local/share'
```

**原因**
Lambda のコンテナイメージは `/tmp` 以外のファイルシステムが読み取り専用。
VOICEVOX engine が起動時に XDG 規約に従い `~/.local/share` へデータを書き込もうとして失敗する。

**解決策**
XDG 環境変数で書き込み先を `/tmp` 配下に向ける。

```dockerfile
ENV XDG_DATA_HOME=/tmp/.local/share
ENV XDG_CACHE_HOME=/tmp/.cache
ENV XDG_CONFIG_HOME=/tmp/.config
```

### 6. `WARNING: Invalid HTTP request received.` (ローカル)

**症状**
```bash
curl -X POST "http://localhost:50021/audio_query?text=ずんだもんです&speaker=3"
# → Invalid HTTP request received.
```

**原因**
日本語テキストを URL エンコードせずに渡すと、uvicorn が HTTP リクエストとして解釈できずに拒否する。

**解決策**
`--data-urlencode` で自動エンコードする。`-G` フラグで POST のクエリパラメータとして付与する。

```bash
curl -G -X POST "http://localhost:50021/audio_query" \
  --data-urlencode "text=ずんだもんです" \
  -d "speaker=3" \
  -o query.json
```

## 動作確認コマンド (通しテスト)

```bash
# ビルド (Apple Silicon では --platform 指定が必須)
docker build --platform linux/amd64 -t voicevox-test aws/lambda/voicevox/

# 起動
docker run --platform linux/amd64 -p 50021:50021 voicevox-test

# Step 1: ヘルスチェック
curl http://localhost:50021/version

# Step 2: audio_query (日本語テキストは --data-urlencode で URL エンコード)
curl -G -X POST "http://localhost:50021/audio_query" \
  --data-urlencode "text=ずんだもんです" \
  -d "speaker=3" \
  -o query.json

# Step 3: synthesis → WAV 出力
curl -X POST "http://localhost:50021/synthesis?speaker=3" \
  -H "Content-Type: application/json" \
  -d @query.json \
  -o output.wav

# Step 4: 再生確認 (macOS)
afplay output.wav
```

## デプロイコマンド

```bash
cd aws
npm install
npx cdk bootstrap   # 初回のみ
npm run deploy
```

デプロイ後の AWS 疎通確認も同様に `--data-urlencode` を使用する。

```bash
BASE_URL="https://<api-id>.execute-api.ap-northeast-1.amazonaws.com"
API_KEY="<your-api-key>"

curl -G -X POST "${BASE_URL}/audio_query" \
  --data-urlencode "text=ずんだもんです" \
  -d "speaker=3" \
  -H "x-api-key: ${API_KEY}" \
  -o query.json

curl -X POST "${BASE_URL}/synthesis?speaker=3" \
  -H "Content-Type: application/json" \
  -H "x-api-key: ${API_KEY}" \
  -d @query.json \
  -o output.wav

# 再生確認 (macOS)
afplay output.wav
```

> **Note:** API キー認証が必要です。詳細は [API 認証ガイド](./02.voicevox_api_authentication.md) を参照してください。
